How This Text Comparison Works

This tool is powered by Google's diff-match-patch library, the same diffing engine used inside products like Google Docs. It finds the shortest set of insertions and deletions that turns the Original text into the Changed text, using an efficient implementation of Myers' diff algorithm.

Because everything runs as JavaScript directly in your browser, comparisons happen instantly with no server round-trip, and your text never leaves your device.

Comparison Modes

  • Word: the default — good for comparing prose, articles, or paragraphs, since it groups changes by whole words instead of single letters.
  • Character: the most granular — useful for short strings, code snippets, or spotting a single typo.
  • Line: treats each line as one unit — ideal for comparing config files, logs, or code where whole lines are added or removed.

"Clean Up Small Edits"

Raw diffs can sometimes report technically-correct but oddly-shaped changes, like splitting one word into several tiny fragments. Enabling this option runs diff-match-patch's semantic cleanup pass, which merges those fragments into more human-readable, meaningful chunks — recommended for most everyday comparisons.

Output Views

  • Unified: one column with both old and new line numbers — closest to a standard git diff, and the most compact for scanning changes quickly.
  • Side by Side: Original and Changed shown in two aligned columns, like a split-view code review — easiest for comparing two full documents visually.
  • Inline: one flowing paragraph with insertions and deletions highlighted in place — best for short strings, sentences, or quick spot-checks where line numbers aren't needed.
