How Basic Auth Encoding Works

HTTP Basic Authentication doesn't encrypt your credentials — it only encodes them, so the transformation is fully reversible by design. This is exactly what's happening above:

username:password Base64 encode Authorization: Basic <encoded>

What Is HTTP Basic Authentication?

HTTP Basic Authentication is a simple scheme built into the HTTP protocol for sending a username and password with a request. The client joins the username and password with a colon (username:password), encodes that string using Base64, and sends it in the Authorization request header prefixed with the word Basic.

It's important to understand that Base64 is not encryption — it's a reversible encoding, meaning anyone who intercepts the header can decode it back into the original username and password in a fraction of a second, exactly like this tool's decoder does. Basic Auth is only safe when sent over HTTPS, where TLS encrypts the entire request (including the header) in transit.

Step-by-Step Example

  • Credentials: username admin, password secret123
  • Joined: admin:secret123
  • Base64 encoded: YWRtaW46c2VjcmV0MTIz
  • Final header: Authorization: Basic YWRtaW46c2VjcmV0MTIz

Developer Quick Reference

  • cURL: curl -u username:password https://api.example.com
  • JavaScript: btoa('user:pass')
  • Python: base64.b64encode(b"user:pass")
  • Bash / Linux: echo -n "user:pass" | base64

Never send Basic Auth credentials over plain HTTP, and avoid using it for anything sensitive in production — prefer token-based schemes (like Bearer tokens or OAuth) where possible.
