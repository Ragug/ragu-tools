How HTTP Status Codes Are Grouped

HTTP status codes are three-digit numbers returned by a server in response to a client's request. The first digit defines the class of response, and the remaining two digits do not have any classifying role. There are five classes defined by the standard: informational responses (1xx), successful responses (2xx), redirects (3xx), client errors (4xx), and server errors (5xx).

Most Common Codes

  • 200 OK: the request succeeded.
  • 301 / 302: the resource has moved, permanently or temporarily.
  • 400 Bad Request: the request was malformed.
  • 401 / 403: authentication or permission problems.
  • 404 Not Found: the resource does not exist.
  • 500 Internal Server Error: something failed on the server.

Developer Quick Reference

  • cURL: curl -o /dev/null -s -w "%{http_code}\n" URL
  • JavaScript (fetch): response.status
  • Python (requests): response.status_code
  • Nginx / Apache logs: status code is the field right after the request line.

Non-Standard & Vendor-Specific Codes

Not every three-digit code you'll see in the wild comes from the official IANA registry. Server software and CDNs define their own codes to describe conditions the standard doesn't cover — Cloudflare's 520-530 range for proxy/origin failures, Nginx's 444/494-499 for connection-level issues, and IIS's 440/449 for session handling are common examples. This reference marks these clearly with a "Non-standard" tag and the responsible vendor, and they can be filtered separately using the "Non-Standard / Vendor" pill above.
